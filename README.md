# 赛程 · 每日足球

每天打开看一眼赛程的小页面：无广告、无推荐、无新闻，只有比赛。
使用 React + Vite 构建，仍然作为静态网站部署到 GitHub Pages。

## 本地开发

需要 Node.js 22.12 或更新版本。

```bash
npm ci
npm run dev
```

打开终端显示的 `/football-schedule/` 地址。预览生产构建：

```bash
npm run build
npm run preview
```

直接双击源文件 `index.html` 不再是运行方式。页面用户继续通过网站或已安装的 PWA 使用，无需安装 Node.js。

验证改动：

```bash
node --test tests/regression.test.js
npm run build
npx playwright install chromium
npm run test:e2e
```

## 使用

- “日 / 7天”切换查看范围：进入“7天”时，从所选日期起连续展示七天，包含跨月日期；左右箭头翻到相邻七天，“今天”（或 `T` / `Home`）回到从今天起的七天。点击日期条中的日期可定位当天比赛；重新打开时若上次日期已过去，七天视图会从今天开始。
- “只看关注”在日视图和七天视图都生效，按开赛时间显示关注球队的比赛；日视图只显示一份比赛，不再重复列出赛事分组。开关和视图偏好会保存在本机，重新打开后继续使用，也会同步到同一浏览器的其他标签页。
  关注球队在已关闭的已知赛事中比赛仍会显示；查询范围保留已选赛事，避免只从一场联赛添加关注后漏掉杯赛。
  尚未关注球队时提供搜索入口；暂无关注比赛与赛程未取得、过期或不完整会分别提示。
- 打开已部署网站，或使用上面的本地开发地址。
- 球队名旁的 ☆ 点一下即关注（★）。关注的球队当天的比赛会置顶到"★ 我的关注"（带赛事标签），
  日期条实心圆点表示有已知的关注球队比赛（含关闭赛事），空心表示其他已开启赛事有比赛，半灰表示所选赛事的赛程未知（缓存缺失或过期）。
- 工具栏“关注”按钮打开关注管理浮层：电脑为右侧抽屉，手机为底部面板；按球队列出已关注项（中文名、赛事），每行附一行“赛程预览”（该队在本地月缓存里的未来比赛，
  没有则显示“暂未查到赛程”），行尾“取消关注”一键取消，按钮上的数字是关注球队数。
  时间有效且未延期的预览可点击或用键盘激活，打开比赛在本机时区对应的日期；沿用现有日/7天导航，今晚视图会转为日视图。
  激活预览后自动收起关注面板；等待加载时，焦点先移到“赛程结果”区域。赛程加载或更新结束后，滚动到对应比赛并移动焦点，优先定位“★ 我的关注”中的那一份。
  若无法确认该场比赛，或当前列表未显示该场，焦点转到现有赛程结果、空列表或错误提示；不补造比赛，也不清除筛选。
  每次激活只定位一次；之后手动切换日期、视图、查看范围或重新打开关注面板，会取消尚未完成的定位，后台刷新不会再次滚动或抢走焦点。
  已取消的比赛不参与关注面板预览，但仍保留在普通赛程中；延期预览保留赛事和对阵，显示“延期 · 时间待定”，不显示原开赛日期时间，也不提供日期跳转。
  预览只查已缓存的月份、零联网，不代表联网查全的完整赛程。
- 关注面板支持按中文名、英文名和简称搜索球队。球队名单优先从本站快照加载并缓存 7 天；快照不可用时尝试 ESPN，失败仍保留旧名单。定时任务同步更新赛程与球队名单。
  面板只是管理入口：关注本身始终生效，不依赖面板是否展开，也不依赖联赛圆点是否开启。
- 关注以球队档案存在浏览器本地（`fs1.followed`，JSON 数组：名称、归一化/别名键、出现过的联赛）。
  匹配以名称为准：同一队换了 ESPN 球队 ID 仍会跟上，同一个 ID 换了队名则不会误跟；旧版纯字符串数组（`id:X` / `name:X` / 裸队名）打开页面时自动迁移，
  只有 ID 没有名字的旧记录先按 ID 匹配，球队在赛程里出现后补全名称与联赛。
- 无比赛日的“关注球队比赛预览”覆盖关注球队所在的赛事，即使这些赛事在筛选中被关闭。
  关闭赛事中的其他球队比赛不参与列表和日期条统计。
- 同一浏览器开多个标签页时，任一标签页增删关注或切换联赛会自动同步到其他已打开的标签页（只吸收外部变更，不会覆盖其他页当天选择的日期等偏好）。
- “今天”按钮（快捷键 `T` 或 `Home`）一键回到今天，翻远了不用一步步翻回来；“刷新”可重新取得赛程。
- 顶部日期条切换日期，也支持键盘 ← → 翻日；日期条上的小圆点表示那天有比赛。手机上日期条保持紧凑、滚动时固定在顶部；“今天”“今晚”和“刷新”位于日期条下方，不随页面滚动固定。
- “今晚”一次展示本机时区 18:00（含）到次日 06:00（不含）开赛的比赛，晚间与次日凌晨分组、按开赛时间排序；两队都已关注的比赛只显示一次。继续遵守赛事筛选和“只看关注”，凌晨 06:00 前保留前一晚，06:00 后自动切换。点击“今天”、日期或翻日按钮回到日视图；可直接切换到7天视图。该范围为试用默认值，需按 [球迷验证约定](docs/ui-copy.md#今晚试用范围与球迷验证) 收集反馈后定稿。
- “赛事筛选”显示已选数量和当前组合摘要，两端默认关闭。点击后电脑打开居中弹窗，手机打开底部面板，通过“俱乐部 / 国家队”标签切换类别，标签显示各组已选数量。
- “全部赛事 / 只看五大联赛 / 只看欧战 / 只看国家队”一键替换当前组合；组内“全选 / 清除”只影响当前类别。可逐项多选，至少保留 1 项，选择立即生效并自动保存；“完成”收起面板。
- 两种浮层都支持关闭按钮、完成、点击遮罩或 Escape 关闭；打开时背景不可操作或滚动，内容在浮层内滚动，关闭后恢复原浏览位置与入口焦点。手机打开关注管理时先聚焦标题，点搜索框再唤起键盘；电脑直接聚焦搜索框。移除最后一支关注球队后焦点留在搜索框，可继续添加；点击赛程预览会关闭浮层并定位目标比赛。
- 键盘可用左右方向键切换赛事类别、空格切换赛事，Tab 焦点限制在当前浮层中。关注球队的比赛仍会显示；“只看关注”模式下可先调整赛事，再切换到全部比赛查看。
- 俱乐部赛事：英超/西甲/德甲/意甲/法甲/欧冠/欧联/中超/英冠/日职/欧协联。
- 成年男子国家队赛事：国际友谊赛、欧国联、世界杯、六大洲世预赛、亚洲杯及预选赛、欧洲杯及预选赛、美洲杯，共 14 项。新用户默认启用国家队赛事；已有用户保留原筛选选择，在“赛事筛选 → 国家队”开启所需赛事即可。
- 可搜索“国足”“中国队”“阿根廷”“Argentina”等名称关注国家队。同一国家队跨赛事只显示一条搜索结果；关注后会查询全部已接入的国家队赛事，关闭赛事中的其他球队仍不显示。
- 赛程数据齐全且当天没比赛时，海报头显示“暂无比赛”，列表显示赛程预览与更早/之后比赛的跳转；首次加载显示“加载中…”，已有比赛的后台更新显示“更新中…”；数据过期或部分联赛不可用、且暂无比赛可确认时显示“赛程待确认”，已有比赛则显示场数和“赛程可能有变动”或“部分赛程未能加载”；页面加载异常且无比赛时显示“暂时无法加载赛程”并可重新加载。
- 比赛时间为本机时区；当前列表有进行中的比赛时，约每分钟自动刷新比分。顶部显示比分自身的更新时间，以及更新中、可能延迟或更新失败后自动重试的提示；失败时保留上次比分，也可点“刷新”立即重试。
  多场进行中的比赛使用最早的比分更新时间，避免其他赛事的新赛程掩盖旧比分；跨日的更新时间附带日期。没有进行中的比赛时显示赛程更新时间。
- 未开赛的比赛显示开赛倒计时（“3 分钟后 / 3 小时后 / 2 天后”，每分钟原地更新，7 天以上仍显示“未开赛”）。
- 打开页面会按日期条上显示的日期（含跨月）预取所需的整月赛程缓存，翻到哪天基本秒出。
- 赛程按月拉取并缓存在浏览器本地：看过的日期再次打开秒出，断网也能看缓存；
  手机首次打开优先使用本站赛程快照（每 3 小时更新，当月及未来月份有效期 6 小时），无需先直连 ESPN。
  刷新失败保留最新快照；过期快照仍会明确提示信息不完整，直播比分继续尝试联网刷新。
  本站快照同时提供完整球队名单，搜索国家队和俱乐部无需先直连 ESPN；名单缓存有效期 7 天，抓取失败保留旧名单。
  过期缓存先展示并提示信息可能不完整，后台静默更新。弱网无缓存时首屏最多等 25 秒；
  数据仍不可用则显示“重试”，不会将未取得数据误判为休赛。

## 手机上用 / PWA

已部署上线：**https://goaltang.github.io/football-schedule/**

手机浏览器（Safari / Chrome）打开后“添加到主屏幕”，就像独立 App 一样使用。
已安装的 PWA 可离线打开页面并查看**已缓存月份**的赛程；未缓存的日期无法离线获取，会显示重新加载。
本地队徽在访问相关比赛时按需缓存；未加载过的队徽和只能从远程回退的新球队图标，离线时可能缺失。PC 可打开部署网站或本地开发服务。

PWA 外壳（`manifest.webmanifest` + `icons/` + `sw.js`）只在 http(s) 下生效；
远程赛程不由 Service Worker 离线回退，以便准确提示缓存过期。开发服务不注册 Service Worker；生产预览和部署网站注册并验证缓存。
部署位置是 GitHub Pages 项目站点，与 `<user>.github.io` 个人主页共存；仓库已公开以启用免费 Pages。

## 数据源：一般怎么解决

这类需求（个人用、只看赛程）常见的三种方案：

1. **免费公开接口（本项目采用）**
   ESPN 站内公开 JSON（`site.api.espn.com`）：免注册、免密钥、CORS 全开，
   覆盖五大联赛、欧冠/欧联/欧协联、英冠、中超、日职等，含未来赛程与比分。
   缺点：非官方公开承诺的接口，字段可能变动——所以数据层全部收敛在 `data.js` 一个文件里，
   真变了只需要改 `fetchMonth` / `normalizeEvent`。
   （TheSportsDB 也是免密钥接口，但免费档对返回条数有硬限制，实测一天只剩 3 条，不适合赛程场景。）

2. **官方免费套餐 + 本地小代理**
   - football-data.org：免费档 12 项赛事（五大联赛、欧冠、英冠、巴甲等），10 次/分钟，赛程/积分榜免费，实时比分要付费（€12/月）。
   - API-Football：免费档 100 次/天、10 次/分钟，数据更细，但轮询实时比分很快会烧穿额度。
   这类接口要么要密钥、要么 CORS 受限，标准做法是加一个很小的本地服务端做两件事：**藏密钥 + 按天缓存**，
   浏览器只访问本地。个人用几百行 Python（FastAPI/甚至标准库）就够。

3. **付费数据商**（Opta / StatsBomb / Sportradar 等）：做正式产品才需要，按年按赛事报价。

另外不建议直接爬国内体育站（懂球帝/直播吧等）：页面结构说变就变，还有合规风险。

通用经验：不管用哪个源，都值得做缓存（本项目按月存 localStorage，服务端方案可存 SQLite/文件），
这样每天打开是秒开的，源站抽风或断网时也能看已缓存的数据；时区一定要在客户端按本地日期切分，
本项目在东八区凌晨 3:00 的比赛会正确归到当天。
图片同理：队徽显示只有 28px，绝不下 500px 原图（130KB）；本项目直接把 64px 缩略图
**打包进 logos/ 目录随项目分发**（懂球帝这类站点就是自托管队徽到国内 CDN 的思路）。
`file://` 打开时本地图标无需网络；PWA 则在访问相关比赛后缓存图标。本地缺失的新球队才回退到远程缩略图（约 6KB）。

## 文件说明

| 文件 | 作用 |
| --- | --- |
| `index.html` / `src/main.tsx` | Vite 和 React 入口 |
| `styles.css` | 样式（系统浅/深色、蓝色强调、分组卡片） |

| `data.js` | 数据层：ESPN 抓取、归一化、按月缓存、时区分桶、空日就近搜索 |
| `app.js` | 状态、动作、加载顺序、轮询和偏好同步 |
| `src/components/` | 日期栏、赛事筛选、关注管理、赛程列表及比赛行 |
| `src/domain/` | 关注匹配、球队搜索和日期格式 |
| `src/types.ts` | 界面与数据接口的 TypeScript 类型 |
| `vite.config.ts` | 构建、静态资源与 PWA 缓存清单 |
| `manifest.webmanifest` / `icons/` | PWA 清单与应用图标（安装到手机主屏用） |
| `sw.js` | Service Worker：应用壳缓存，托管后离线可用 |
| `tests/regression.test.js` | 数据缺失、过期缓存、跨月与邻近比赛日回归测试 |

维护时运行回归测试、构建和浏览器测试。浏览器运行构建产物，不需要 Node.js。

## 部署与迁移

合并迁移 PR 前，在仓库 **Settings → Pages → Source** 将发布源设为 **GitHub Actions**。若已先合并，切换来源后手动运行 `deploy` 工作流即可发布。`deploy.yml` 安装依赖、运行回归测试、构建 `dist/` 并发布。

赛程快照继续每三小时更新。快照工作流提交数据后显式构建并发布，确保机器人提交不会漏掉部署。

构建时复制 `logos/`、`icons/` 和 `snapshot/`。`vite.config.ts` 将真实 JS/CSS 文件清单写入产物 `sw.js`，缓存版本由 HTML 和资源清单生成。以后无需手动给脚本加 `?v=`。

现有 `fs1.enabled`、`fs1.followed`、日期/视图偏好和月缓存格式保持兼容；新增 `fs1.onlyFollowed` 保存“只看关注”开关。已有 PWA 更新时继续使用同一个路径和清单。
页面文案、状态提示和操作命名遵循 [文案与反馈约定](docs/ui-copy.md)。

## 常见改动

- **加/减赛事**：`config.js` 里 `LEAGUES` 增删一行（`id` 为 ESPN 赛事标识，如 `por.1` 葡超、`fifa.friendly` 国际友谊赛）；国家队赛事加 `group: 'national'`。
  增加后跑一次 `node tools/refresh-logos.js` 把新赛事队徽下载到本地；仅刷新国家队可运行 `node tools/refresh-logos.js --national`。再运行 `node tools/build-snapshot.js` 和 `node tools/build-teams-snapshot.js` 更新赛程和球队名单，部署后由原有定时工作流继续每 3 小时更新。
- **球队中文名**：`team-names.js` 增加一行；大小写、音调、`FC`/`AS` 前缀后缀等写法差异会自动归一，
  不用为同一支球队写多条。查漏有两个途径：访问 `/football-schedule/tools/zh-coverage.html`，一次列出所有联赛里还没收录的队名
  （附可直接粘贴的空条目）；或平时看球时留意浏览器 console 的“未收录中文名”提示。
- **换数据源**：只需重写 `data.js` 的 `fetchMonth`（拉原始数据）与 `normalizeEvent`（归一化为
  `{id, league, start, status, minute, home, away}`，其中 `home/away = {name, teamId, logo, score, winner}`），
  界面层不用动；`teamId` 用于命中本地图标 `logos/<teamId>.png`。
