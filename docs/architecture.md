# 前端模块维护

页面按业务组件拆分。新增功能先确定数据、规则和展示各放在哪里。

| 改动 | 位置 |
| --- | --- |
| ESPN 字段、请求、月缓存、快照 | `data.js` |
| 赛事配置 | `config.js` |
| 关注身份、旧记录迁移、名称别名 | `src/domain/following.js` |
| 球队搜索、目录去重 | `src/domain/catalog.js` |
| 页面数据加载、轮询、用户偏好 | `app.js` |
| 展示和局部交互 | `src/components/` |
| 界面接口类型 | `src/types.ts` |

`app.js` 对外提供动作和稳定快照，React 用 `useSyncExternalStore` 订阅。用户动作保存对应偏好后发布快照。渲染和查询不保存偏好，也不发起请求。

日期切换和视图切换继续使用请求序号：过时的请求或后台更新不能覆盖当前页面。`start()` / `stop()` 管理事件和计时器，组件卸载时解除订阅、失效未完成加载并清理轮询。

领域逻辑先保留 JavaScript。新增组件使用 TypeScript，并通过 `src/types.ts` 描述数据边界。逐步为领域模块补类型即可，不必在一次 UI 改动中改写缓存规则。

## 示例：新增一个数据模块

1. 将外部数据归一化为稳定的数据对象。
2. 将纯计算规则放入 `src/domain/`。
3. 在控制器中加入状态和明确动作；需要保存时使用独立的存储键。
4. 创建组件，通过 props 接收数据和动作。组件内部的临时展开状态可以使用 React state。
5. 数据规则用 Node 测试，用户交互用 Playwright 验证。

当前回归测试在独立 VM 中隔离缓存、时钟和网络。涉及界面的断言由真正的 React 组件生成，不保留第二份旧 HTML 渲染逻辑。浏览器测试覆盖键盘焦点、日期/视图切换、搜索、关注和跨标签同步。

## PWA 和发布

`npm run build` 会生成 `dist/`，复制快照和图标，并生成完整资源缓存清单。缓存版本包含构建指纹。源文件 `sw.js` 定义缓存策略，产物 `dist/sw.js` 包含真实文件名。

主分支改动由 `deploy.yml` 发布。机器人定时快照提交不会触发另一个工作流，因此快照工作流有独立的构建发布任务；两个发布流程共享 Pages 并发组。

首次切换需要将 GitHub Pages 的 Source 设为 GitHub Actions。开发、测试和 PR 不修改在线站点。
