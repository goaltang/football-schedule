# 页面文案与反馈约定

页面用于查看足球赛程和比分。文案应帮助用户理解比赛内容、当前情况和下一步操作。

## 用词

- 标题描述内容：赛程、我的关注、赛程预览、关注球队赛程预览。
- 操作描述动作：刷新、重新加载、关注、取消关注、查看当天比赛。
- 筛选统一称为“赛事筛选”，按“俱乐部”和“国家队”分组。
- 比赛状态统一使用：未开赛、进行中、完场、延期、取消、中断、延迟。
- 页面不展示缓存、快照、公开接口、球队 ID、内部赛事编号和原始异常。这些信息保留在代码、日志和维护文档中。
- 不根据空列表猜测国际比赛日、休赛或网络故障。不把搜索失败写成没有匹配球队。
- 赛程覆盖不全时，不承诺最近一场、下一场或完整比赛数量。使用“预览”“暂未查到”等表达。

## 提示时机

| 情况 | 主文案 | 显示方式 |
| --- | --- | --- |
| 首次加载且暂无比赛可展示 | 加载中… | 骨架或加载面板，提供屏幕阅读器状态标签 |
| 已有比赛，正在更新 | 更新中… | 顶部轻提示，保留比赛列表，不显示错误面板 |
| 当前列表有进行中的比赛 | 进行中比分约每分钟自动更新 · 可能有延迟 | 日期下方轻提示，报头显示比分自身的更新时间 |
| 进行中的比赛正在更新 | 正在更新比分… · 当前显示上次结果 | 保留比分和上次更新时间，完成后切换提示 |
| 进行中的比分超过 2 分钟未更新，或更新时间未知 | 比分可能已延迟 · 将自动尝试更新 | 不以月度赛程的有效期判断实时比分的新鲜度 |
| 进行中的比分刷新失败 | 比分更新失败 · 稍后自动重试 | 保留上次比分；仅部分进行中比赛受影响时使用“部分比分更新失败” |
| 已有比赛，部分赛程加载失败 | 部分赛程未能加载 | 指明受影响的赛事或日期，提供重新加载说明 |
| 已有比赛，信息过期 | 赛程可能有变动 | 说明比赛时间和比分可能变化，提供刷新说明 |
| 赛程未取得或不完整，暂无比赛可确认 | 赛程待确认 | 说明暂时无法确认是否有比赛，提供重新加载 |
| 页面加载异常，暂无比赛可展示 | 暂时无法加载赛程 | 简短说明和重新加载按钮，不展示原始错误 |
| 数据齐全，确实没有比赛 | 暂无比赛 / 这7天暂无比赛 | 建议切换日期或调整赛事，不猜测休赛原因 |
| 仅查看关注且尚未关注球队 | 还没有关注球队 | 提供“添加关注球队”和“查看全部比赛”入口 |
| 仅查看关注且赛程齐全、确实没有对应比赛 | 当天暂无关注球队的比赛 / 这7天暂无关注球队的比赛 | 建议切换日期或查看全部比赛；信息不完整时继续使用“赛程待确认” |
| 关注面板没有查到未来比赛 | 暂未查到赛程 | 行内文字，不宣称球队没有比赛 |
| 关注面板查到时间有效且未延期的比赛 | 赛程预览：日期时间 · 赛事 · 对阵 | 可用键盘激活的按钮；可访问名称说明“查看当天比赛”并标明球队和本机日期 |
| 关注面板预览为延期比赛 | 赛程预览：延期 · 时间待定 · 赛事 · 对阵 | 行内文字，保留赛事和球队，不展示原开赛日期时间，不提供日期跳转 |
| 就近预览覆盖不全 | 其他日期可能还有比赛，以下赛程仅供参考。 | 普通辅助文字，不使用错误警示样式 |

日视图和周视图共用 `app.js` 的 `UI_TEXT`、`scheduleStatus`。更新中和失败是不同状态；已有比赛时，不能再声称无法确认这一天或这一周是否有比赛。

关注面板预览只扫描本地已缓存月份，不发起联网查询，不承诺完整覆盖或真实最近一场。已取消比赛不参与预览候选，但仍保留在普通赛程中；没有可用候选时显示“暂未查到赛程”。可操作预览打开比赛在本机时区对应的日期，沿用现有日/7天导航；从今晚进入时切换为日视图。预览不可用或已延期时不提供日期跳转，关注和取消关注行为保持一致。

用户点击或用键盘激活可操作预览后，自动收起关注面板。等待加载时，焦点先移到“赛程结果”区域，后台更新不重复移动这一临时焦点。赛程加载或更新结束后，滚动到对应比赛并移动焦点，优先定位关注分组中的那一份。若无法确认该场比赛，或当前列表未显示该场，焦点转到现有赛程结果、空列表或错误提示，不补造比赛、不清除筛选。每次激活只定位一次；之后手动切换日期、视图、查看范围或重新打开关注面板，会取消尚未完成的定位。重新打开面板时，搜索框照常获得焦点，后续赛程更新不打断搜索。定位完成后，后台刷新不再滚动或抢走焦点。

比分提示由 `src/domain/score-updates.js` 统一生成，只统计当前列表显示的进行中比赛。每场比赛携带自己的数据获取时间与本次刷新结果；多场比赛取最早时间，有时间未知的比赛则不显示统一更新时间。失败回退到仍有效的赛程数据也必须保留比分刷新失败提示。周视图其他日期的后台加载不能遮住已完成请求的比分状态。跨日时间附带月/日，跨年附带年份。正常的每分钟时钟更新不改变比分更新时间；没有进行中的比赛时显示“赛程更新于”。

## 今晚试用范围与球迷验证

“今晚”的试用默认值为本机时区 18:00（含）至次日 06:00（不含），按开赛时间筛选，已完场的比赛仍保留比分。用户已选择此默认值，球迷试用反馈尚未收集。范围集中在 `src/domain/tonight.js`，验证后再调整。

- 报头显示“今晚”“18:00–次日06:00”及具体起止日期；列表分为“晚间”和“次日凌晨”，一次展示跨日比赛。
- 午夜到 06:00 继续展示前一晚，回访也恢复当前这一晚；到 06:00 或页面重新可见时切换到新一晚。
- 比赛按开赛时间排序、按比赛 ID 去重，赛事筛选和只看关注继续生效；不重复显示关注分组。
- 数据齐全且范围内无赛时显示“今晚暂无所选赛事或关注球队的比赛”；只看关注时显示“今晚暂无关注球队的比赛”。加载失败或覆盖不全继续显示“赛程待确认”及重新加载入口，保留已知比赛。

合并前请让 3–5 位经常看晚间和凌晨足球的球迷试用分支预览，手机和电脑各覆盖一次。请他们完成“找到今晚想看的比赛”和“凌晨再次查看这一晚比分”两个任务，然后记录：

1. 18:00 是否漏掉他们认为属于今晚的比赛？希望从几点开始？
2. 06:00 是否太早？是否需要延长到 08:00？
3. 午夜后的日期分组是否清楚，是否减少了切换日期？

这是待验证的产品假设，技术测试通过不代表球迷验证已完成。

## 维护要求

- 简短、具体，用同一个词指同一种内容或操作。
- 每处反馈只表达与当前操作有关的事实；正常后台更新不重复弹出提示。
- 提示涉及操作时，必须有可用入口；未确定原因时不要求用户检查网络。
- 保留日期、比赛状态、更新时间、时区和必要的信息完整性说明。
- 检查日/周视图、首次加载、后台更新、部分失败、过期信息、确认无赛和关注预览。
- 修改页面资源时，检查构建产物 `sw.js` 的 `CACHE` 和资源清单。Vite 按资源哈希自动生成新缓存版本，无需手动增加脚本版本参数。
